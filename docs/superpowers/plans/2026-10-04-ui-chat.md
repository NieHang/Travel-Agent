# Travel UI Chat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 实现旅游 UI 协议、模型 Structured Output 和按意图分流的确定性操作处理。

**Architecture:** 协议 Schema 为类型的唯一来源。UIResponseService 复用模型工厂生成并校验组件，UIFlowService 管理会话和状态，Controller 提供身份隔离及请求校验。独立查询保留规划草稿。

**Tech Stack:** NestJS 12、LangChain、Zod 3、TypeScript、Vitest、Supertest。

**Spec:** `docs/superpowers/specs/2026-10-04-ui-chat-design.md`（用户已确认）。

## Global Constraints

- 所有新增协议代码位于 `services/chat/src/llm/ui-protocol/`；使用项目现有 `.js` 导入方式。
- 八类组件与五类表单字段沿用规格规定的字段名、枚举及业务语义。
- 使用 `z.discriminatedUnion('type', ...)` 和 `model.withStructuredOutput(aiUIResponseSchema)`。
- 不增加供应商接入、预订、支付、前端或数据库迁移；不修改 Turborepo 配置或命令。
- 会话闲置 30 分钟过期，历史保留最近 20 条消息，最多保存 1000 个会话。
- 认证用户与 sessionId 组合隔离；同会话串行、响应验证成功后才提交。
- 无可信旅游数据来源时不得声称实时价格、库存或已验证的 500 米酒店结果。

## Review Focus

- 输入已经提供旅游类型和需求时应跳过相应问题，而非重复向导（Task 3）。
- 查询切换不能清空草稿，旧确认按钮不能确认另一版路线（Task 3）。
- 模型返回结构合法但场景错误的组件时必须拒绝并保留会话（Task 2、3）。
- 未知或重复表单字段、无效日期及单选多值不能改变状态（Task 1、3）。
- 同名 sessionId 在不同认证用户间必须完全隔离，过期后旧操作不能执行（Task 3、4）。

**Interfaces:** `UIFlowService.chat(sessionId: string, input: string): Promise<AIUIResponse>` 和 `handleAction(sessionId: string, action: UIAction): Promise<AIUIResponse>`。sessionId 参数为 Controller 生成的用户作用域键；消费 Task 2 的生成接口。

- [x] 写流程测试并确认红灯：类型选择 → 缺失需求 form → 路线草案 → confirmation + steps → confirmed；取消回到 reviewing_itinerary。
- [x] 增加跳步测试：已知旅游类型不重复问；独立酒店搜索直接展示，保留用户提供的地点、距离、预算等查询约束（西湖附近 500 米作为测试用例）；查询中 resume_planning 恢复草稿。
- [x] 增加操作校验测试：组件不存在、旧组件、重复确认、跨会话、单选多值、未知选项、必填缺失、重复/未知字段、无效日期、人数非正整数和负预算均拒绝。
- [x] 增加事务与生命周期测试：模型拒绝后旧组件仍有效；同会话并发串行；20 条历史截断；假时钟推进 30 分钟后 Action 返回 404；1000 个未过期会话上限阻止新建。
