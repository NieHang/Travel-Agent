# 用户层 · 前端设计

- 日期：2026-10-03
- 范围：`clients/chat-web`
- 配套文档：[后端与契约设计](./2026-10-03-user-layer-backend-design.md)
- 粒度：按钮级
- 技术栈：Next.js 16、Tailwind 4、HeroUI、Motion、TanStack Query、next-intl

## 1. 目标

为 Hilda 提供落地页、登录与注册、对话页（聊天区、历史抽屉、右侧静态面板）。视觉语言参考 roam 设计稿：高饱和纯色舞台、深色胶囊、白色卡片、弹簧动效。

成功标准：

1. 未登录用户在落地页输入需求，登录或注册后该需求自动发出并收到流式回复。
2. 登录用户能在抽屉里浏览、搜索、重命名、删除历史对话，并继续任意一段对话。
3. 刷新页面后登录态自动恢复；一个标签页登出，其他标签页同步登出。
4. 界面可在中文与英文间切换。
5. 桌面按设计稿两栏呈现；窄屏下所有功能可用。

## 2. 不做的事

深色模式、个人资料页、修改昵称的界面、重新生成与失败重试按钮、多人协作头像组、真实的行程/酒店/路线/热点数据、保存行程与预订的真实功能、URL 语言前缀、服务端路由保护。

## 3. 实现约束

- Next 16 与 HeroUI 在 Tailwind 4 下的具体接法，在实施计划阶段先读已安装包自带的文档再定。本文只规定要达到的行为。
- 所有请求与响应类型来自 `@autix/contracts`，前端不重复定义。

## 4. 路由

| 路径 | 路由组 | 访问规则 |
|---|---|---|
| `/` | `(public)` | 任何人可访问 |
| `/login`、`/register` | `(auth)` | 已登录时跳 `/chat` |
| `/chat` | `(app)` | 新对话；未登录跳 `/login?next=/chat` |
| `/chat/[id]` | `(app)` | 具体会话；未登录跳 `/login?next=/chat/{id}` |

路由保护在客户端完成。refresh Cookie 属于后端源且限定了路径，Next 服务端读不到它。`(app)` 的布局根据鉴权状态渲染：`loading` 显示全屏品牌加载动效，`guest` 跳登录页，`authed` 渲染页面。刷新页面时会先出现约一次请求时长的加载动效，这是 access token 只放内存的固有代价。

`next` 参数只接受以单个 `/` 开头的站内路径；以 `//` 开头、含协议或其他形式的值一律当作 `/chat`。

## 6. 状态与数据流

### 6.1 鉴权

- 一个模块级 store，通过 `useSyncExternalStore` 订阅，不引入状态库。状态为 `loading | authed | guest`，持有内存中的 `accessToken` 与 `user`。
- 应用启动时静默调用一次 `POST /api/auth/refresh` 恢复登录态。
- API 客户端自动加 `Authorization` 头，所有请求带 `credentials: 'include'`。
- 收到 `TOKEN_EXPIRED`：触发刷新并把原请求重试一次，且仅一次。
- 刷新是单飞的：并发的多个 `TOKEN_EXPIRED` 共用同一个刷新请求。
- 刷新返回 `REFRESH_INVALID`：等待 300ms 后再试一次（应对多标签页并发）；仍失败则置为 `guest`。
- 刷新返回 `REFRESH_REUSED`：直接置为 `guest`，登录页显示 `登录状态已失效，请重新登录 / Your session ended. Please sign in again`。
- 多标签页：通过 `BroadcastChannel` 广播登出，其余标签页收到后置为 `guest`。

### 6.2 服务端状态

- 会话列表、消息列表用 TanStack Query 的无限查询，对应游标分页。
- 搜索词防抖 300ms 后作为查询键的一部分。
- 重命名与删除用乐观更新，失败回滚并弹提示。
- 登出时清空全部查询缓存。

### 6.3 流式对话

`useChatStream(conversationId)` 负责：

- 用 `fetch` 发起请求并读取响应流（原生 `EventSource` 无法携带 `Authorization` 头）。
- 解析 SSE 事件，维护一份「正在生成的消息」本地状态：累计文本、需求列表、阶段（`sending | streaming | idle`）。
- `user_message` 到达时把用户消息写入查询缓存。
- `done` 或 `error` 到达时把助手消息写入查询缓存，清空本地状态。
- `stop()` 中止请求；中止后把已累计的文本作为一条 `partial` 助手消息写入缓存，并使该会话的消息查询失效以便与服务端对齐。
- 流开始前请求失败（网络错误、4xx、5xx）：不写缓存，把文字还给输入框，弹提示。
- 组件卸载或 `conversationId` 变化时自动 `stop()`。

### 6.4 落地页输入的暂存

点击「开始规划」且未登录时，把输入写入 `sessionStorage`（键 `hilda:pendingPrompt`），跳 `/login?next=/chat`。登录或注册成功进入 `/chat` 后，页面发现暂存内容：先清除暂存，再创建会话、跳 `/chat/{id}`、自动发送。先清后发保证刷新页面不会重复发送。

## 7. 双语

- next-intl，URL 不带语言前缀，语言存 Cookie `hilda_locale`。同一链接对不同用户可能显示不同语言，这对落地页的搜索引擎收录不利，属已接受的取舍。
- 首次访问按浏览器 `Accept-Language` 决定，无法判断时用中文。
- 登录后以 `User.locale` 为准并写回 Cookie。
- 切换语言：写 Cookie；已登录时同时调用 `PATCH /api/users/me`，该请求失败不回滚界面语言，也不提示。
- 后端错误按 `code` 映射词典文案。未知的 `code` 显示通用文案 `出了点问题，请重试 / Something went wrong. Try again`。
- 模型回复的语言不受界面语言控制，跟随用户输入。
- 相对时间（「3 天前」）与数字格式随界面语言变化。

下文所有文案以「中文 / English」给出。

## 8. 视觉系统

色值取自参考图，实现时可微调，语义角色固定。

### 8.1 色板

| 角色 | 色值 | 用途 |
|---|---|---|
| `ink` | `#1B1535` | 深色胶囊、输入框、右侧面板底、正文字色 |
| `lime` | `#C6E82F` | 主操作与选中态 |
| `paper` | `#FFFFFF` | 卡片、助手气泡、建议 chip |
| `stage-yellow` | `#FFC93C` | 落地页、登录页、注册页背景 |
| `stage-orange` | `#FF7A1A` | 「行程」标签下的页面背景 |
| `stage-purple` | `#7B61FF` | 「酒店」 |
| `stage-green` | `#0FAE7B` | 「路线」 |
| `stage-pink` | `#FF5FA2` | 「热点」；也用于次级强调按钮 |
| `danger` | `#E5484D` | 删除确认、表单错误 |

对比度规则：

- `lime` 上的文字一律用 `ink`。
- 白色文字只出现在 `ink` 底上。
- 所有舞台色上直接放置的文字都用 `ink`。参考图里紫、绿、粉底上的浅色小字对比度不足，此处有意偏离。

### 8.2 字体

- 拉丁：Plus Jakarta Sans（500、700、800）。中文：Noto Sans SC（500、700、900）。经 `next/font` 自托管。
- 大标题用最重字重，行高 0.95。字距：拉丁 `-0.04em`，中文 `-0.02em`。
- 字号：落地页标题 `clamp(56px, 9vw, 128px)`；面板标题 56；区块标题 24；正文 16；辅助 14；标注 12。

### 8.3 形状与层次

- 胶囊（按钮、标签、chip、输入框）全圆角；卡片 20px；右侧面板与认证面板 40px。
- 阴影只有一档：`0 12px 32px rgba(27, 21, 53, 0.18)`，用于浮在舞台色上的元素。面板内的卡片不加阴影。
- 间距以 4px 为基数。

### 8.4 弹簧预设

集中定义在 `lib/motion.ts`，组件不得自行写弹簧参数。

| 名称 | stiffness / damping | 用于 |
|---|---|---|
| `snappy` | 500 / 30 | 按钮按压回弹、chip 点击、表单错误晃动 |
| `smooth` | 380 / 32 | 标签选中指示器、列表项重排、就地编辑 |
| `drawer` | 300 / 34 | 历史抽屉、移动端底部面板 |
| `gentle` | 120 / 18 | 页面入场、消息气泡出现、浮动卡片 |

背景色切换不用弹簧（颜色过冲会出现脏色），用 450ms 缓出过渡。

### 8.5 动效原则

- 动效只表达状态变化：出现、消失、选中、按压、加载。唯一的装饰性循环是落地页浮动卡片的缓慢漂浮。
- 入场统一为「上移 12px + 淡入」；列表项依次延迟 40ms，最多错开 8 项。
- 系统开启「减少动态效果」时，所有位移与缩放改为纯淡入淡出，漂浮停止。

### 8.6 交互元素的通用状态

下文每个按钮默认继承这些状态，表格里只写差异。

| 状态 | 表现 |
|---|---|
| 悬停 | 放大到 1.03（`snappy`） |
| 按压 | 缩小到 0.96（`snappy`） |
| 键盘聚焦 | 2px 描边并外扩 2px；浅色底上为 `ink`，`ink` 底上为 `lime` |
| 禁用 | 不透明度 0.4，无悬停与按压反馈，指针为禁止 |
| 加载 | 文案换为转圈，宽度不变，期间不可再次触发 |

所有图标按钮都有读屏标签。所有可点击元素的触摸区域不小于 44px。

## 13. 移动端

断点：宽度小于 1024px。

- 聊天区占满全屏，右侧面板不直接显示，P1 与 P2 从顶部栏移除。
- 输入框上方增加胶囊按钮 `查看行程 / View trip`，点击后面板以 `drawer` 从底部升起，占屏幕高度的 92%。
- 底部面板顶部有拖动条与关闭按钮（读屏标签 `关闭 / Close`）。向下拖动超过面板高度的四分之一、点击关闭按钮、按 Esc 均可收起。
- P1 位于底部面板顶部，可横向滚动；P2 位于其右侧。页面背景色照常跟随 P1。
- 热点卡片由四列变为两列。
- 历史抽屉占满全宽。
- 落地页浮动卡片隐藏，建议 chip 换行排列。

## 14. 测试

前端目前没有测试设施，以下工具均为新引入。

| 层 | 工具 | 覆盖 |
|---|---|---|
| 单元 | Vitest | SSE 事件解析（含跨块拆分的事件）；`next` 参数过滤；并发 `TOKEN_EXPIRED` 只触发一次刷新；原请求只重试一次；`REFRESH_INVALID` 的延迟重试；表单校验规则；`zh` 与 `en` 词典的键完全一致 |
| 组件 | Vitest + Testing Library，网络用 MSW 模拟 | 登录与注册表单的每个错误分支；`useChatStream` 的完成、出错、手动停止、流开始前失败；暂存输入只消费一次；重命名与删除的乐观更新与回滚；抽屉的焦点限制与 Esc；四个面板的本地交互 |
| 端到端 | Playwright，后端以 `LLM_FAKE=1` 运行并连接测试库 | 落地页输入 → 注册 → 自动发送 → 收到流式回复与需求卡片 → 抽屉里出现该会话 → 重命名 → 删除 → 退出；刷新后登录态恢复；两个标签页同步退出；切换语言后文案变化且刷新后保持 |
